- Share chain work
  - "695","Share identity binding using midstate trick from original p2pool","pool2win","2026-10-08"
    - Fixes a DoS where attackers could build many share headers for one found
      share and flood peers' header queues; sha256 midstate trick limits one
      bitcoin PoW to one share header. PoW check itself was already correct.
    - Changes share header and block formats → requires a chain reset (no
      migration for testnet4). Scheme documented at
      https://docs.p2poolv2.org/architecture/share_commitment.html
  - "691","Move share commitment to share header","pool2win","2026-10-07"
    - Share commitment was in the bitcoin coinbase scriptSig, making the share
      blockhash malleable; now in the share header using the p2pool midstate
      trick. Some share header fields still not committed to in the coinbase –
      tightened further in #695.
  - "689","Search highest work valid block as mining base","pool2win","2026-10-06"
    - Mining base search was over all !Invalid blocks (attackable with non-PoW
      headers, long chains needing arbitrary caps); now limited to BlockValid
      blocks with valid PoW.
  - "683","Handle peer liveness and recovery","pool2win","2026-10-05"
    - Explicit ping-failure handling (libp2p no longer does it), per-peer
      connection count tracking to stop flaky peers reconnecting, close idle
      connections, connection metrics for grafana, handshake fix so branches
      with different tips can sync.
  - "682","Refactor node actor select switch","pool2win","2026-10-05"
    - Replaces big dispatch table that caused backpressure from slow jobs, and
      the loop sending swarm events to itself (potential deadlocks). Cleaner
      shutdown with named tokio tasks and JoinSets.
