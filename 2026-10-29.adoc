|pool2win
a|*Count uncle share work in sharechain work*

* Chain work now includes uncle work – without it uncles don't make the
  chain stronger, which was the point of including them. Closes #601.
* New rule: an uncle referenced from any ancestor can't be referenced again
  as an uncle. Header sync requires uncles to be received and validated for
  position and work.
* Consensus change: no fork mechanism used, the chain will be reset
  again. The reason is this is a fundamental enough rule and I didn't
  want to add fork rules at this level.

|https://github.com/p2poolv2/p2poolv2/pull/730[#730]
|pool2win
a|*build: fix vendored libzmq SIGSEGV on AVX-default compilers*

* Root cause: vendored libzmq is built without `HAVE_POSIX_MEMALIGN`, so
  64-byte aligned structs got 16-byte aligned malloc chunks; GCC 15 on
  Ubuntu 26.04 targets x86-64-v3 and emits 32-byte aligned stores, crashing
  on first connect.
* Defines `HAVE_POSIX_MEMALIGN` and `ZMQ_CACHELINE_SIZE` via per-target
  CXXFLAGS; coverage job unpinned from ubuntu-24.04 again.

|https://github.com/p2poolv2/p2poolv2/pull/729[#729]
|msgilligan
a|*GHA Workflows: use explicit ubuntu-26.04 runners over ubuntu-latest*

* Replaces `ubuntu-latest` with `ubuntu-26.04` so OS upgrades happen when we
  choose (prompted by the ubuntu-26 surprise above). Also moves the arm
  docker runner to `ubuntu-26.04-arm` to match x86_64.

|https://github.com/p2poolv2/p2poolv2/issues/722[#722]
|pool2win
a|*Track coinbase root height as value is accounted for in txs*

* Today every output gets the oldest input's height, so mixing an old share
  with a fresh one expires all outputs early (hurts share trading). Per
  stevenroose's suggestion, track the height per output, like value.
* Rules: coinbase outputs get the share's height; value may move to a lower
  height, never a higher one; fee comes from the oldest value; outputs
  expire below `H - PAYOUT_DEPTH`; coinbase maturity unchanged.
* Validation: sort inputs/outputs by height, cover each output from the
  highest remaining inputs.
* Open: explicit field in the serialized output (breaks Bitcoin tx format,
  sighash, PSBT, Electrum) vs deriving it with a fixed oldest-first flow.
