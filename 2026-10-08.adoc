==== Share chain work

[cols="1,2,8"]
|===
|PR |Author |Title / description

|https://github.com/p2poolv2/p2poolv2/pull/695[#695]
|pool2win
a|*Share identity binding using midstate trick from original p2pool*

* Fixes a DoS where attackers could build many share headers for one found
  share and flood peers' header queues; sha256 midstate trick limits one
  bitcoin PoW to one share header. PoW check itself was already correct.
* Changes share header and block formats → requires a chain reset (no
  migration for testnet4). Scheme documented at
  https://docs.p2poolv2.org/architecture/share_commitment.html

|https://github.com/p2poolv2/p2poolv2/pull/691[#691]
|pool2win
a|*Move share commitment to share header*

* Share commitment was in the bitcoin coinbase scriptSig, making the share
  blockhash malleable; now in the share header using the p2pool midstate
  trick.
* Some share header fields still not committed to in the coinbase –
  tightened further in #695.

|https://github.com/p2poolv2/p2poolv2/pull/689[#689]
|pool2win
a|*Search highest work valid block as mining base*

* Mining base search was over all !Invalid blocks (attackable with non-PoW
  headers, long chains needing arbitrary caps); now limited to BlockValid
  blocks with valid PoW.

|https://github.com/p2poolv2/p2poolv2/pull/683[#683]
|pool2win
a|*Handle peer liveness and recovery*

* Explicit ping-failure handling (libp2p no longer does it).
* Per-peer connection count tracking to stop flaky peers reconnecting;
  close idle connections; connection metrics for grafana.
* Handshake fix so branches with different tips can sync.

|https://github.com/p2poolv2/p2poolv2/pull/682[#682]
|pool2win
a|*Refactor node actor select switch*

* Replaces big dispatch table that caused backpressure from slow jobs, and
  the loop sending swarm events to itself (potential deadlocks).
* Cleaner shutdown with named tokio tasks and JoinSets.

|johnnyasantoss
a|*`pool_signature` is consensus-critical but user-tweakable config*

* pool_signature (from local config) is pushed into the coinbase scriptSig
  used to reconstruct the merkle root in `validate_bitcoin_payout`, so
  nodes with different values reject each other's blocks and get stuck
  (also wedges candidate index: "Mismatch in top height").
  `difficulty_multiplier` is the same hazard class.
* Jungly: There's three issues reported here. Need to disentangle and
  address them
** pool signature as the title says
** sync stuck issue that needs to be verified
** difficulty
