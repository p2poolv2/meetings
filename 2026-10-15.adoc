[cols="1,2,8"]
|===
|PR |Author |Title / description

|https://github.com/p2poolv2/p2poolv2/pull/709[#709]
|pool2win
a|*Wait for share maturity before paying them*

* Maturity was enforced for spends but not for payout distribution; shares
  now only enter PPLNS payouts after 6048 confirmations (70% of the daily
  share block target, close to bitcoin's 100-block coinbase maturity), so
  miners aren't paid for shares that could still be reorged out.
* Closes #552. Documented at
  https://docs.p2poolv2.org/architecture/pplns_accounting.html

|https://github.com/p2poolv2/p2poolv2/pull/707[#707]
|pool2win
a|*Mine on bitcoin active chain*

* Design doc `docs/architecture/mine-on-bitcoin-chain.md` plus TLA+ spec
  (with attacker config) for #652: a share's coinbase pays a window share
  only if its bitcoin prev is on (or one block off) the bitcoin chain the
  paying share builds on; share messages carry the needed bitcoin headers;
  shares are accepted only once their bitcoin prev header is known.
* Work on fabricated bitcoin blocks never paid, hostile forks paid for at
  most their first two blocks, orphan-race losers still paid.
* Docs/spec only; implementation is #653. Might not start on this for
  a while.

|https://github.com/p2poolv2/p2poolv2/pull/703[#703]
|pool2win
a|*Remove difficulty multiplier for share chain PPLNS window*

* PPLNS window difficulty multiplier is now a constant in
  code. Leaving it to node operators will break consensus.

|https://github.com/p2poolv2/p2poolv2/pull/699[#699]
|pool2win
a|*Take pool signature out of consensus*

* `pool_signature` no longer part of the coinbase reconstruction used in
  validation, so nodes with different signatures agree on validity; sim
  runs now use different pool sigs.
